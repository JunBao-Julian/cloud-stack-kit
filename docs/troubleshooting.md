# 排错

| 现象 | 检查与处理 |
| --- | --- |
| `Validate` 拒绝地址 | 将示例 IP 换为 VPS 公网 IPv4；域名、内网地址和保留地址不支持 |
| npm / GitHub 下载失败 | 先确认已有网络；可填写无凭据的 `bootstrapProxy` 供 npm 使用 |
| SSH 主机指纹变化 | 通过云平台核验是否重装或更换主机，不要直接删除 `known_hosts` |
| 代理 TCP 可用，UDP 失败 | 检查云安全组和 UFW 是否都开放代理 UDP 端口；确认 Clash 节点支持 UDP、TUN/严格路由已开启 |
| API 端口不通 | 检查 SSH 守护日志、隧道密钥权限、远端服务；不要公开开放 8080 作为替代 |
| 本机端口已占用 | 检查是否已有另一套实例，先停止旧实例或给新实例分配独立端口；工具不会杀死无关进程 |
| `Activate` 要求管理员 | 用相同 Windows 账号提升 PowerShell；换管理员账号会切换用户配置目录 |
| 第一次 Clash 初始化未完成 | 手动打开一次 Clash 完成提示，再重跑 `Windows` 阶段 |
| `Gateway` 要求本人操作 | 在面板亲自阅读并完成要求，随后重跑；不能用脚本代签 |
| 网关健康但模型请求失败 | 健康检查不验证上游授权；检查账号状态、分组、模型权限和额度 |
| 浏览器国内站点较慢 | 默认所有浏览器公网流量都走 VPS，可选择 `browserMode: split`；这会允许国内站点看到直连出口 |
| IPv6 检测没有结果 | 可能没有可用 IPv6 出口或 DNS 无 AAAA；不是完整防泄漏证明，需实际浏览器测试 |

## 检测网站中的多个 IP

混合直连和代理本身可能产生多个出口。先对照分流策略判断：默认列出的浏览器公网 TCP/UDP 应经过 VPS，其他应用访问国内目标可能直连。

浏览器列表为 Edge、Chrome、Firefox、Brave、Opera、Vivaldi、Arc。改名程序、嵌入式 WebView 和新增浏览器需要额外规则及实测。STUN 常用端口有单独代理规则，但不能覆盖所有自定义协议与端口。

TUN 需实际运行才能接管普通浏览器 UDP；只设置 HTTP 系统代理无法保证这一点。退出 Clash 后本机可能恢复直连，本工具不是系统级永久断网保护器。

时区、语言或出口 IP 一致不代表匿名，也不能证明第三方账号合规或保证不会封禁。

## 反馈问题

提供 Windows/Ubuntu 版本、所用阶段、工具版本与脱敏错误摘要。不要上传 `config.json`、运行目录、浏览器配置、`client.json`、`panel-login.txt`、SSH 私钥、数据库或包含令牌的截图。可用 `config.example.json` 改成文档示例地址来复现。
